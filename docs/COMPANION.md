# Companion skins — format v2

The companion is a small pixel-art creature that lives on the player (PLAN.md §4b). A **skin** is one creature: its
grid, its colour palettes and the frames of every animation the companion's brain can ask for. This doc is the source
of truth for the skin file. `src/companion/skin.ts` implements it, and `src/companion/companion.test.ts` checks every
bundled skin against it.

**Format history:**
- **v1** (C1): the first format.
- **v2** (C2a, 2026-10-18): adds two optional keys per animation.
  - `steps`: how far each frame moves the creature, which the bookworm's inching needs.
  - `anchor`: where a pose rests, which `sit` needs.

  v1 files are rejected. Every bundled skin is generated, so moving to v2 was a regeneration.

Status (M2 C2a): the renderer, the validator, the registry, the brain (`src/companion/brain.ts`), the
`Companion` component and the dev-only Companion lab exist.
- **Bundled skins:**
  - `test-dummy`, a deliberately plain placeholder generated by `scripts/gen-test-dummy.mjs`.
  - The three species from the D1 design round, all kept: `pilcrow` (the default), `bookworm` and `cassette`
    (`docs/design/d1-concepts.png`). C6 lets you choose between them.
- Nothing in the production player shows a companion yet (C2b).

## Where skins live

- One folder per skin: `companions/<id>/companion.json`.
- Bundled skins are listed in `src/companion/registry.ts`, keyed by id. User-installed skins come later, with the
  loader (M3).

## The file

```json
{
  "id": "test-dummy",
  "name": "[NEEDS COPY]",
  "format": 2,
  "grid": 16,
  "anchor": { "x": 8, "y": 14 },
  "palettes": {
    "default": ["#1d1b2e", "#f2a65a", "#fff3d6"],
    "night": ["#e8e6f2", "#4b5a8a", "#ffd166"]
  },
  "animations": {
    "idle": { "fps": 1, "loop": true, "durations": [2800, 160], "frames": [["................", "…"], ["…"]] },
    "…": {}
  }
}
```

| Key | Rule |
|---|---|
| `id` | Lowercase letters, digits and hyphens, starting with a letter or digit, at most 40 characters. Same as the folder name and the registry key. |
| `name` | Never written in the file by hand. It must equal the COPY.md entry **Companion skin name — `<id>`**, or `[NEEDS COPY]` while that entry has no wording (CLAUDE.md: displayed text comes from COPY.md only). |
| `format` | `2`. Any other value is rejected. |
| `grid` | Width and height in art pixels, 8–32. Every frame is `grid` rows of `grid` characters. |
| `anchor` | `{ x, y }` in art pixels, inside the grid: the foot point. The bottom edge of that pixel rests on the surface the creature stands on. |
| `palettes` | Named colour lists. Must include `default`. Names follow the `id` rule. Each list holds 1–8 `#rrggbb` colours, and every list has the same length. |
| `animations` | Exactly the required animations below, no others. |

No other keys are allowed anywhere: an unknown key is an error, not ignored.

### Frames

A frame is a list of strings, one string per row, one character per art pixel:

- `.` is transparent.
- `1`–`8` is a palette slot: `1` is the palette's first colour, and so on. A slot the palettes don't have is an error.

Palette skins share one set of frames: switching palettes swaps colours, never shapes.

**Frame 0 of a looping animation is its rest pose.** The brain may hold it for as long as it needs:
- when the change budget is short;
- while asleep, once `sleep` has played a few loops.

So frame 0 should be the pose that looks right standing still. Eyes open for `idle` and `sit`; for `sleep`, the
frame with the "z".

Frames are drawn **facing right**. The renderer mirrors them within the grid when the creature walks left (whole art
pixels, so still crisp).

### Animations

| Key | Rule |
|---|---|
| `fps` | Whole frames per second, 1–12. |
| `loop` | `true` repeats. `false` plays once and holds the last frame. |
| `frames` | 1–8 frames. |
| `durations` | Optional. Milliseconds per frame, one per frame, each 50–10 000. Overrides `fps`, e.g. a long open-eyes frame and then a short blink. |
| `steps` | Optional (v2). Art pixels the creature moves forward on entering each frame, one per frame, each 0–8. If absent, `walk` moves 1 per frame and every other animation stays put. The pilcrow and cassette walk `[2, 2]`. The bookworm inches with `[4, 0]`: its tail catches up to its planted head (0), then its head reaches forward (4). |
| `anchor` | Optional (v2). This animation's own resting point, overriding the skin's. `sit` needs one: the creature sits on a row in the middle of its frame and its legs hang below the edge. |

**Required animations** (the brain's states, PLAN.md §4b). What each one should show:

| Animation | Shows | Loops in the dummy |
|---|---|---|
| `idle` | Standing still; an occasional blink | yes |
| `walk` | Walking along an edge | yes |
| `sit` | Sitting on an edge, legs over the side | yes |
| `climb` | Climbing a side edge | yes |
| `hang` | Hanging under the bottom edge | yes |
| `sleep` | Asleep (paused or nothing playing); an emote such as a pixel "z" is part of the frame | yes |
| `wake` | Waking up | no |
| `react` | Reacting to a click or a track change; emotes are pixel icons, never text | no |
| `held` | Being carried by the pointer | yes |
| `fall` | Falling after a drop | yes |
| `land` | Landing | no |

A skin that is missing one of these, or has any other error, is rejected as a whole. The companion must be able to
show every state.

## Cost: keep animations slow

In Stanza's transparent window, every visible change re-composites the whole window, which costs about 3–6 ms of CPU.
The budget is about two changes a second on average (C0 spike, docs/DECISIONS.md 2026-10-17). So:

- Prefer long holds: `idle`, `sit` and `sleep` should change rarely. The dummy holds 2.8–3.2 s between blinks.
- `sleep` is shown whenever music is paused or nothing is playing, which can last hours. The dummy changes its frame
  every 4 s.
- Keep fast frame rates to short, one-off animations (`wake`, `land`).
- The brain enforces a hard cap: at most `BUDGET_PER_MINUTE` (90) visible changes in any rolling minute.
  - Optional changes (another blink loop, another sleepy loop, a walk) only start when the last minute leaves room
    for all of their frames.
  - Changes caused by the music always happen: falling asleep, waking, reacting to a track change.
- Typical rate while music plays is 48–58 changes a minute (simulated, an hour per skin). While paused it's zero
  once `sleep` has played 3 loops.

## How it renders

- **Pixels to SVG:** each frame becomes one `<path>` per palette slot, made of merged horizontal runs
  (`src/companion/spritePaths.ts`), drawn with `shape-rendering: crispEdges`. There are no image files.
- **Colours:** slot `n` has the class `mp-pet-c<n>` and is filled with the custom property `--mp-pet-<n>`, set from the
  chosen palette.
- **Scale:** one art pixel is `round(2 × dpr) / dpr` CSS px, which is always whole device pixels: 2 at 100%, 3 at 125%
  and 150%, 4 at 200%.
- **Box:** the sprite's layout box is the art's size rounded up to a multiple of 4 CSS px (`spriteBoxPx` in
  `src/companion/pixel.ts`). The art sits at the box's top-left, and any spare strip stays transparent. A length that
  isn't a multiple of 4 CSS px can't be stored exactly in the engines' 1/64 px layout units at 125%, and Chromium then
  blends the art's last row into the backdrop (C1, docs/DECISIONS.md 2026-10-18).
- **Frames:** advanced by JS timers, never by CSS or Web Animations. On the player, the brain owns them (one timer,
  `Companion.tsx`); in the lab's gallery, `useFrame` in `src/companion/Sprite.tsx` does. Any running CSS animation
  costs about 2% of a core in the transparent window, even while it shows nothing new.
- **Placement on an edge** (`src/companion/place.ts`): the pose's anchor pixel rests on the edge. Positions are whole
  art pixels from a grid-aligned origin, applied as a `transform`, so they're whole device px too. Sitting is not
  allowed where the dangling legs would hang over a blocked stretch of the edge (`noSitRanges`, from the frames' rows
  below the sit anchor, both facings).

## The Companion lab

`?lab=companion` on the dev server (dev builds only) shows:
- **Live cards** at the top: every skin on a mock card's top edge, run by its brain. Buttons stand in for the music:
  play, pause, stop, next track.
- **Each skin in context** at the top, at real size around a plain mock card (no text), on a light and a dark backdrop:
  - walking, asleep and sitting on the top edge;
  - hanging under the bottom edge;
  - climbing the left side.
- **Every skin × palette × animation** on a light and a dark backdrop. Each one appears at real size and zoomed,
  and each animation's frames are laid out side by side.

The scene places each pose by its contact with the edge:
- **Top-edge poses:** the production placement (`placeOnEdge`), with `sit` on its own anchor.
- **`hang`:** the frame's top-most opaque row, until C3 defines it.
- **`climb`:** its right-most column, until C3 defines it.

- `?lab=companion&pause` holds every animation on its first frame (for screenshots).
- `?lab=companion&skin=<id>` shows one skin and leaves out the live cards.
- `?lab=companion&live` shows only the live cards. The fake-clock e2e uses it: the gallery's ~570 animated sprites would
  otherwise swamp every clock step.

`e2e/companion-lab.spec.ts` checks the lab:
- Everything renders, with no console errors.
- Frames advance with no CSS/Web animation running.
- Non-looping animations stop.
- Every skin's real-size sprites are crisp at 100/125/150/200%: only palette and backdrop colours, and every colour
  run a whole number of art pixels.
- The scenes put every pose on whole device px.

`e2e/companion-brain.spec.ts` runs the live cards on Playwright's paused fake clock and counts the DOM's visible
changes:
- **Within budget, on the edge:** while music plays, every creature stays within the change budget and on its edge.
  This time-lapse runs in Chromium only; the count is React's commits, which don't depend on the engine.
- **Asleep:** about 3 s after the music stops, every creature falls asleep, then shows no changes at all.
- **Play, track change, stop:** play wakes them, a new track makes them react, and stop sends them to sleep.
- **Reduced motion:** still poses, and no changes on their own.

`src/companion/brain.test.ts` simulates whole hours per skin with a seeded generator.

## Drawing tools

- `scripts/companions/pixels.mjs` holds the drawing helpers:
  - `frame` composes parts onto a 16×16 frame, and placing a pixel outside the frame throws.
  - `flipX`, `flipY`, `rotCCW` and `rotCW` flip and turn: a quarter turn of the walk gives the climb.
  - `shift` and `recolor` move and recolour.
  - `shape` outlines a filled mask automatically and fills its inside with a pattern.
- `scripts/companions/<id>.mjs` draws one creature; `node scripts/gen-companions.mjs` writes their `companion.json`
  files. `test-dummy` has its own `scripts/gen-test-dummy.mjs`.
- `node scripts/companion-sheet.mjs <out.png> [id …]` builds a review sheet (needs the dev server on port 1420).
  It shows each skin around the lab's mock card, every animation's frames zoomed, and every palette on light and
  dark.

## Adding a skin

1. Create `companions/<id>/companion.json` following this doc.
2. Add it to `SKINS` in `src/companion/registry.ts`.
3. Add a **Companion skin name — `<id>`** entry to docs/COPY.md (the wording is the owner's: leave `[NEEDS COPY]`),
   and set `name` to match.
4. Run `npx vitest run src/companion` and `npx playwright test e2e/companion-lab.spec.ts`, then look at it in the lab
   on both backdrops.

## Originality

All companion art is made for Stanza. Other pets (PLAN.md research table) are inspiration for behaviour and format
only:
- No traced, recoloured or adapted sprites.
- No copied code.
- Each new creature gets an originality check against the references, logged in docs/DECISIONS.md.

  lab reads those contacts off the art.
