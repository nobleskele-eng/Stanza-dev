# Companion skins — format v2

The companion is a small pixel-art creature that lives on the player (PLAN.md §4b). A **skin** is one creature: its
grid, its colour palettes and the frames of every animation the companion's brain can ask for. This doc is the source
of truth for the skin file. `src/companion/skin.ts` implements it, and `src/companion/companion.test.ts` checks every
bundled skin against it.

**Format history:**
- **v1** (C1): the first format.
- **v2** (C2a, 2026-10-18): adds two optional keys per animation.
  - `steps`: how far each frame moves the creature, which the bookworm's inching needs.
  - `anchor`: where a pose rests, which `sit` needs.

  v1 files are rejected. Every bundled skin is generated, so moving to v2 was a regeneration.

Status (M2 C6b): the renderer, the validator, the registry, the brain (`src/companion/brain.ts`), the
`Companion` component and the dev-only Companion lab exist.
- **Bundled skins:**
  - `test-dummy`, a deliberately plain placeholder generated by `scripts/gen-test-dummy.mjs`.
  - The three species from the D1 design round, all kept: `pilcrow` (the default), `bookworm` and `cassette`
    (`docs/design/d1-concepts.png`). You choose between them in the right-click menu (C6a, below).
- **Choosing (C6a):** the right-click menu's companion items are pictures with no text (your call). First the on/off
  cassette, awake when on. Then a submenu labelled with your creature, holding the three species and then your
  species in each of its palettes. The chosen species and palette are drawn awake, the rest asleep. Picking one turns
  the companion on as that creature, and the choice is saved app-wide (`pickCompanion`, `src/theme/appearance.ts`).
  A palette belongs to its species, so a new species starts in its default palette. The test dummy isn't offered
  (`SPECIES`, `src/companion/registry.ts`), though a stored one still loads for the lab and the tests.
- The production player shows the companion when it's turned on (C2b), travelling the card's whole outline (C3b).
  It can be clicked, picked up and dropped there too (C4b, contract v9): it avoids `.mp-artwork`, and its box is part
  of the window's hit region.
- It has a shelf inside the card in the four card themes (C5b, contract v10): `theme.json` `companion.shelf`
  declares one level with the source badge's base, from the card's left side to the badge, not drawn. The Micro Pill
  has none.

## Where skins live

- One folder per skin: `companions/<id>/companion.json`.
- Bundled skins are listed in `src/companion/registry.ts`, keyed by id. User-installed skins come later, with the
  loader (M3).

## The file

```json
{
  "id": "test-dummy",
  "name": "[NEEDS COPY]",
  "format": 2,
  "grid": 16,
  "anchor": { "x": 8, "y": 14 },
  "palettes": {
    "default": ["#1d1b2e", "#f2a65a", "#fff3d6"],
    "night": ["#e8e6f2", "#4b5a8a", "#ffd166"]
  },
  "animations": {
    "idle": { "fps": 1, "loop": true, "durations": [2800, 160], "frames": [["................", "…"], ["…"]] },
    "…": {}
  }
}
```

| Key | Rule |
|---|---|
| `id` | Lowercase letters, digits and hyphens, starting with a letter or digit, at most 40 characters. Same as the folder name and the registry key. |
| `name` | Never written in the file by hand. It must equal the COPY.md entry **Companion skin name — `<id>`**, or `[NEEDS COPY]` while that entry has no wording (CLAUDE.md: displayed text comes from COPY.md only). |
| `format` | `2`. Any other value is rejected. |
| `grid` | Width and height in art pixels, 8–32. Every frame is `grid` rows of `grid` characters. |
| `anchor` | `{ x, y }` in art pixels, inside the grid: the foot point. The bottom edge of that pixel rests on the surface the creature stands on. |
| `palettes` | Named colour lists. Must include `default`. Names follow the `id` rule. Each list holds 1–8 `#rrggbb` colours, and every list has the same length. |
| `animations` | Exactly the required animations below, no others. |

No other keys are allowed anywhere: an unknown key is an error, not ignored.

### Frames

A frame is a list of strings, one string per row, one character per art pixel:

- `.` is transparent.
- `1`–`8` is a palette slot: `1` is the palette's first colour, and so on. A slot the palettes don't have is an error.

Palette skins share one set of frames: switching palettes swaps colours, never shapes.

**Frame 0 of a looping animation is its rest pose.** The brain may hold it for as long as it needs:
- when the change budget is short;
- while asleep, once `sleep` has played a few loops.

So frame 0 should be the pose that looks right standing still. Eyes open for `idle` and `sit`; for `sleep`, the
frame with the "z".

Frames are drawn **facing right**. The renderer mirrors them within the grid when the creature walks left (whole art
pixels, so still crisp).

### Animations

| Key | Rule |
|---|---|
| `fps` | Whole frames per second, 1–12. |
| `loop` | `true` repeats. `false` plays once and holds the last frame. |
| `frames` | 1–8 frames. |
| `durations` | Optional. Milliseconds per frame, one per frame, each 50–10 000. Overrides `fps`, e.g. a long open-eyes frame and then a short blink. |
| `steps` | Optional (v2). Art pixels the creature moves forward on entering each frame, one per frame, each 0–8. If absent, `walk` and `climb` move 1 per frame and every other animation stays put. The pilcrow and cassette walk `[2, 2]`. The bookworm inches with `[4, 0]`: its tail catches up to its planted head (0), then its head reaches forward (4). Each species' `climb` is its walk turned a quarter, so it keeps the walk's `steps` (C3b). |
| `anchor` | Optional (v2). This animation's own contact point, overriding the default. `sit` needs one: the creature sits on a row in the middle of its frame and its legs hang below the edge. `climb` and `hang` touch the card differently (below) and have their own defaults. |

**Required animations** (the brain's states, PLAN.md §4b). What each one should show:

| Animation | Shows | Loops in the dummy |
|---|---|---|
| `idle` | Standing still; an occasional blink | yes |
| `walk` | Walking along an edge | yes |
| `sit` | Sitting on an edge, legs over the side | yes |
| `climb` | Climbing a side edge | yes |
| `hang` | Hanging under the bottom edge | yes |
| `sleep` | Asleep (paused or nothing playing); an emote such as a pixel "z" is part of the frame | yes |
| `wake` | Waking up | no |
| `react` | Reacting to a click or a track change; emotes are pixel icons, never text | no |
| `held` | Being carried by the pointer | yes |
| `fall` | Falling after a drop | yes |
| `land` | Landing | no |

**Where `climb` and `hang` touch the card** (C3a, 2026-10-29). Every other animation stands on an edge: its anchor
pixel's bottom edge rests on it.
- `climb` is drawn **facing a wall on its right**, and mirrored on the card's right side. Its anchor pixel's right edge
  touches the wall, and the pixel's row is its height on the side. Default: the right-most opaque column of any frame,
  at the top-most opaque row of any frame. So at the side's top it's level with the card's top.
- `hang`'s anchor pixel's top edge touches the bottom edge from below. Default: the skin anchor's column, at the
  top-most opaque row of any frame.

**`held`, `fall` and `land`** (C4a, 2026-11-01). While it's carried or falling, the creature is on no surface: its
sprite box is wherever the pointer put it, and its anchors don't apply.
- `held` plays while it's carried, as the budget allows (it's a resting loop). Frame 0 should look right held still.
- `fall` is shown for the whole fall, which moves on its own clock (a step every 40 ms, speeding up, and slowly again
  after each turn), so a fall's frames change only as fast as its `durations` or `fps` say. A fall down a card's face
  lasts about a second.
- `land` stands on the top like `idle` (the skin anchor) and plays once.
- Carried or falling, the `held` and `fall` art (every frame, the way it faces) stays off the artwork, so neither may
  reach further than a sprite's box from the grid's edges. A fall onto the top ends on its line, so **`fall`'s lowest
  opaque row must be no lower than `land`'s anchor row**, or its last steps would dip onto the card, and onto artwork
  that starts at the card's top. Not validated: `place.test.ts` checks it for every bundled skin, dropping each one from
  every place it can be carried, with three artwork layouts.

A skin that is missing one of these, or has any other error, is rejected as a whole. The companion must be able to
show every state.

## Cost: keep animations slow

In Stanza's transparent window, every visible change re-composites the whole window, which costs about 3–6 ms of CPU.
The budget is about two changes a second on average (C0 spike, docs/DECISIONS.md 2026-10-17). So:

- Prefer long holds: `idle`, `sit` and `sleep` should change rarely. The dummy holds 2.8–3.2 s between blinks.
- `sleep` is shown whenever music is paused or nothing is playing, which can last hours. The dummy changes its frame
  every 4 s.
- Keep fast frame rates to short, one-off animations (`wake`, `land`).
- The brain enforces a hard cap: at most `BUDGET_PER_MINUTE` (90) visible changes in any rolling minute.
  - Optional changes (another blink loop, another sleepy loop, a walk) only start when the last minute leaves room
    for all of their frames.
  - Changes caused by the music always happen: falling asleep, waking, reacting to a track change. So do changes
    caused by the pointer (C4a): a click's reaction, a pick-up, a fall, a landing.
  - Being carried moves the creature with the pointer. Those moves aren't the creature's own changes, and the budget
    doesn't count them: dragging it costs what dragging any element costs, for as long as you drag.
- Typical rate while music plays is 48–58 changes a minute (simulated, an hour per skin). While paused it's zero
  once `sleep` has played 3 loops.

## How it renders

- **Pixels to SVG:** each frame becomes one `<path>` per palette slot, made of merged horizontal runs
  (`src/companion/spritePaths.ts`), drawn with `shape-rendering: crispEdges`. There are no image files.
- **Colours:** slot `n` has the class `mp-pet-c<n>` and is filled with the custom property `--mp-pet-<n>`, set from the
  chosen palette.
- **Scale:** one art pixel is `round(2 × dpr) / dpr` CSS px, which is always whole device pixels: 2 at 100%, 3 at 125%
  and 150%, 4 at 200%.
- **Box:** the sprite's layout box is the art's size rounded up to a multiple of 4 CSS px (`spriteBoxPx` in
  `src/companion/pixel.ts`). The art sits at the box's top-left, and any spare strip stays transparent. A length that
  isn't a multiple of 4 CSS px can't be stored exactly in the engines' 1/64 px layout units at 125%, and Chromium then
  blends the art's last row into the backdrop (C1, docs/DECISIONS.md 2026-10-18).
- **Frames:** advanced by JS timers, never by CSS or Web Animations. On the player, the brain owns them (one timer,
  `Companion.tsx`); in the lab's gallery, `useFrame` in `src/companion/Sprite.tsx` does. Any running CSS animation
  costs about 2% of a core in the transparent window, even while it shows nothing new.
- **Placement on an edge** (`src/companion/place.ts`): the pose's anchor pixel rests on the edge (`placeOnEdge`).
  Around the whole card (`placeAround`, C3a), the sides run from the card's top down and the bottom from its left; the
  climb and hang anchors touch them as above. Positions are whole
  art pixels from a grid-aligned origin, applied as a `transform`, so they're whole device px too. Sitting is not
  allowed where the dangling legs would hang over a blocked stretch of the edge (`noSitRanges`, from the frames' rows
  below the sit anchor, both facings).

## The Companion lab

`?lab=companion` on the dev server (dev builds only) shows:
- **Live cards** at the top: every skin on a mock card's top edge, run by its brain. Buttons stand in for the music:
  play, pause, stop, next track.
- **Around cards** (C3a): the same, but each creature travels the card's whole outline. At an end of the top it may
  turn the corner (half the time), climb down the side in short legs with pauses, hang under the bottom, then climb
  back up. With the music off it holds still wherever it is; off the top it doesn't sleep or react. They have their own
  seeds. The production player does the same since C3b, in a window with the pet's box as a margin on every side.
- **Pick it up** (C4a), on both kinds of live card:
  - **Click** a creature on the top for a reaction. Asleep, it stirs (`wake`) and dozes off again.
  - **Press and move** at least 4 px to pick it up. It keeps the spot you grabbed and follows the pointer over the card
    and within a sprite's box around it (the production window's margin; above the top edge on the top-only cards). It
    never goes over the artwork (CLAUDE.md): pointing there pushes it off the nearest way.
  - **Let go** and gravity decides:
    - From above the top it falls onto it, speeding up, and plays `land`. Feet within 3 art px below the top's line
      catch it, and it steps up onto it.
    - From over the card it falls down the card's face and catches the bottom edge, hanging. The artwork in the way
      stops it: it slides off the nearer edge and falls on. Slid off the card's side, it grabs that side instead.
    - Beside a side it clings there at once and climbs back up; under the card it hangs from the bottom at once.
  - Its fall never goes up and never crosses the artwork.
  - Under reduced motion it can still be carried, holding still, and a drop puts it straight on the top.
  - The production player does the same since C4b (contract v9). `e2e/companion-player.spec.ts` drives it in every
    theme: a click, a pick-up (the window never starts dragging), carrying over the artwork (pushed off) and the card,
    and a drop over the card that falls and catches an edge. Every step is checked: inside the window, never over the
    artwork, and at rest over no part.
- **Shelf cards** (C5a): a taller mock card with a mock source badge at its foot, and a shelf (drawn here as a line)
  from the card's left side to beside the badge, level with the badge's foot.
  - **What a shelf is:** a floor inside the card. The creature idles, walks, sits, sleeps and reacts there as on the
    top.
  - **Trimmed to fit:** `measureShelf` (`src/companion/measure.ts`) keeps only the positions where none of its floor
    poses (`FLOOR_ANIMATIONS`, both facings) puts an opaque pixel over a part. The lab's 112 px shelf ends up 88–90 px:
    a pose any further along would touch the badge.
  - **Doors:** a shelf must touch a side of the card (within an art pixel). That end is its door. Climbing that side, a
    leg stops level with the shelf, and it mostly steps in (70%). Walking to the door end, it steps back out onto the
    side a little more often than not (60%) and climbs on, up or down. A shelf that touches no side is no shelf: a
    creature dropped there could never leave.
  - **A regular spot** (your call, C5b): at the top's end on the door's side it turns the corner 90% of the time (50%
    elsewhere). Simulated on T1's card, that's about a quarter of the playing time on the shelf, its first visit
    usually within half an hour, and the rest of the outline still travelled.
  - **Drops:** falling down the card's face, the shelf catches it unless something to slide off is higher up. Feet
    within 3 art px below the shelf's line step up onto it.
  - **Reduced motion, or the shelf going away:** it goes back to the top, straight above where it was.
- **Each skin in context** at the top, at real size around a plain mock card (no text), on a light and a dark backdrop:
  - walking, asleep and sitting on the top edge;
  - hanging under the bottom edge;
  - climbing the left side.
- **Every skin × palette × animation** on a light and a dark backdrop. Each one appears at real size and zoomed,
  and each animation's frames are laid out side by side.

The scene places each pose with the brain's own placement (`placeAround`): the top-edge poses on their anchors, `hang`
and `climb` on theirs.

- `?lab=companion&pause` holds every animation on its first frame (for screenshots).
- `?lab=companion&skin=<id>` shows one skin and leaves out the live cards.
- `?lab=companion&live` shows only the live cards, `?lab=companion&around` only the around cards, and
  `?lab=companion&shelf` only the shelf cards. The fake-clock e2e uses them: the gallery's ~570 animated sprites would
  otherwise swamp every clock step.

`e2e/companion-lab.spec.ts` checks the lab:
- Everything renders, with no console errors.
- Frames advance with no CSS/Web animation running.
- Non-looping animations stop.
- Every skin's real-size sprites are crisp at 100/125/150/200%: only palette and backdrop colours, and every colour
  run a whole number of art pixels.
- The scenes put every pose on whole device px.

`e2e/companion-brain.spec.ts` runs the live cards on Playwright's paused fake clock and counts the DOM's visible
changes:
- **Within budget, on the edge:** while music plays, every creature stays within the change budget and on its edge.
  This time-lapse runs in Chromium only; the count is React's commits, which don't depend on the engine.
- **Asleep:** about 3 s after the music stops, every creature falls asleep, then shows no changes at all.
- **Play, track change, stop:** play wakes them, a new track makes them react, and stop sends them to sleep.
- **Reduced motion:** still poses, and no changes on their own.
- **Around the card** (Chromium): until every surface has been visited, each creature's drawn pixels touch the card
  from outside on a side or under the bottom, and stay in the scene.
- **Paused off the top:** no change at all for 5 minutes, on the same surface; it moves again with the music.
- **With a shelf** (C5a, Chromium): each creature is dropped onto the shelf. Then every 2 s (simulated), on the shelf
  its anchor rests on the shelf's line and no drawn pixel covers the artwork, a bar or the badge. Its only ways on and
  off the shelf are the left side's door. The run goes until one has left and come back on its own.

`e2e/companion-pointer.spec.ts` (C4a, Chromium and WebKit) drives the around cards with the mouse on the fake clock:
- Each creature takes the pointer and carries `data-no-drag`.
- Carried over the card (it is over it), the artwork's middle and corner, and past its room, every drawn pixel stays
  off the artwork and in its room. Dropped above the top, it falls, lands and stands on the top's line where it was
  let go.
- Dropped over the card, it falls down the card's face (more than 3 steps, over the card) and hangs touching the
  bottom, below where it was let go.
- Dropped onto the artwork's top edge, it slides off and falls past it, every frame clear of it, and hangs.
- Dropped beside the left side, it clings there touching the side; under the card, it hangs touching the bottom.
- Every step of every fall is checked against the artwork and the room.
- A click makes it react; asleep, a click wakes it, and it's asleep again 2 s later.
- Dropped above a shelf card's shelf (C5a), it falls onto it. For 20 s after, while it's on the shelf, its anchor
  rests on the shelf's line and no pixel covers a part.

In the production player (C5b): `e2e/companion-player.spec.ts` drops the pet above each theme's bottom-left corner.
In a card theme it lands on the shelf, its anchor level with the badge's base, then lives there for 10 minutes
(Chromium) with every step checked: inside the window and over no part, on and off only by the left side. In the
Micro Pill it never lands on a shelf. `e2e/companion-shelf.spec.ts` lays out every card theme × every fixture in both
engines and runs the layer's own `shelfLine` and `measureShelf` on the real boxes, for every species at 100% and
125%: a shelf with its door is left every time, at least 16 art px long (the shortest is 36).

`src/companion/brain.test.ts` simulates whole hours per skin with a seeded generator. With the lab's shelf, three seeds
per skin cover every surface; every move on or off the shelf is at its door, at the exact positions.

## Drawing tools

- `scripts/companions/pixels.mjs` holds the drawing helpers:
  - `frame` composes parts onto a 16×16 frame, and placing a pixel outside the frame throws.
  - `flipX`, `flipY`, `rotCCW` and `rotCW` flip and turn: a quarter turn of the walk gives the climb.
  - `shift` and `recolor` move and recolour.
  - `shape` outlines a filled mask automatically and fills its inside with a pattern.
- `scripts/companions/<id>.mjs` draws one creature; `node scripts/gen-companions.mjs` writes their `companion.json`
  files. `test-dummy` has its own `scripts/gen-test-dummy.mjs`.
- `node scripts/companion-sheet.mjs <out.png> [id …]` builds a review sheet (needs the dev server on port 1420).
  It shows each skin around the lab's mock card, every animation's frames zoomed, and every palette on light and
  dark.

## Emotes

The creatures' only "words" are two pixel emotes, drawn in a skin's accent slot (polished in C6b with you):
- **Sleep:** a 3×4 Z, the same glyph in both frames, drifting up a step from one to the next. The cassette's shell
  leaves no room above it, so its z sways a pixel sideways instead. A 2-pixel-wide z can't hold a diagonal and reads as
  a "c".
- **React:** a 5×4 heart (`.5.5. / 55555 / .555. / ..5..`); 3×3 reads as a "Y". The pilcrow's reaction is a hop, then
  a landing crouch under the heart: standing, it leaves no room above itself for one. The bookworm's heart is still the
  dot of its "i". The cassette shows hearts in its window instead.

## Adding a skin

1. Create `companions/<id>/companion.json` following this doc.
2. Add it to `SKINS` in `src/companion/registry.ts`.
3. Add a **Companion skin name — `<id>`** entry to docs/COPY.md (the wording is the owner's: leave `[NEEDS COPY]`),
   and set `name` to match.
4. Run `npx vitest run src/companion` and `npx playwright test e2e/companion-lab.spec.ts`, then look at it in the lab
   on both backdrops.

## Originality

All companion art is made for Stanza. Other pets (PLAN.md research table) are inspiration for behaviour and format
only:
- No traced, recoloured or adapted sprites.
- No copied code.
- Each new creature gets an originality check against the references, logged in docs/DECISIONS.md.

## Open for later slices

- **Corner art (C3c).** At a corner the creature switches straight from walking to climbing (or climbing to hanging)
  in one change. A short transition animation per corner would read better; it's art, designed with the owner.
- **Moving along the bottom.** `hang` has no step, so it hangs where it came down, at a corner end of the bottom.
- **Accessory attachment points** for the D2 design round.
- **Hopping down to a shelf from the top**, rather than only through its door (C5a's DECISIONS.md entry says why
  not yet).

`hang` and `climb` contacts were settled in C3a (above) without a format change: no bundled skin gives those
animations their own `anchor`, and nothing placed them before.

A format change bumps `format` and updates this doc in the same change.
